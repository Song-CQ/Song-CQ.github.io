Unity SkinnedMeshRenderer重叠动画闪烁问题排查与解决

Unity Shader 渲染 性能优化 踩坑记录
Unity 渲染
发布日期:   2024-03-13

写在开头

作为一个经常与Unity打交道的开发者，遇到渲染问题并不稀奇。但这次的问题着实让我费了一番功夫——两个SkinnedMeshRenderer重叠，静止时完美显示，一播放动画就开始闪烁。这种”动起来就出问题”的现象，往往是最难调试的。

本文将完整记录这个问题的发现、分析到解决的全过程，希望能帮助遇到类似问题的同行少走弯路。

问题描述

现象

  • 场景：一个角色模型，包含两个SkinnedMeshRenderer
  • 基础层：不透明材质，负责角色身体
  • 覆盖层：透明特效材质，负责装备/特效显示（带透明通道）
  • 静止时：完美显示，覆盖层贴合正常
  • 动画时：覆盖层出现像素闪烁
  • 视角快速切换：同样会触发闪烁
  • Overdraw视图下：闪烁消失

环境信息

项目 内容
Unity版本 2021.3.x
基础层Shader Anime Shading/Character/Plain (Queue=Geometry+101 ≈2000)
覆盖层Shader J3/Particles/Additive (Queue=Transparent=3000)
渲染管线 内置渲染管线
平台 Windows / Android

复现步骤

  1. 准备一个包含两个SkinnedMeshRenderer的模型
  2. 基础模型使用不透明材质
  3. 覆盖层使用透明特效材质
  4. 播放模型动画
  5. 观察覆盖层区域出现像素闪烁
  6. 切换到Overdraw视图模式，闪烁消失

排查过程

第一步：排除基础问题

刚开始以为是材质设置问题，逐一检查了：

  • ✅ 透明通道是否正确
  • ✅ 渲染队列是否合适
  • ✅ 混合模式是否正确
  • ✅ Stencil操作是否冲突

一切看起来都正常。

第二步：关键线索——Overdraw视图

在翻阅Unity文档时，突然想到可以用Overdraw视图看看。切换到Overdraw视图后，奇迹发生了——闪烁消失了！

这个线索太关键了：

  • Overdraw视图会忽略深度测试，显示所有像素的绘制次数
  • 说明两个模型都在正确渲染
  • 问题出在深度测试环节

第三步：锁定问题类型

这就引出了图形学中的一个经典问题：Z-fighting（深度冲突）

当两个面几乎完全共面时，它们在深度缓冲区中的值会非常接近。深度缓冲区精度有限（通常是24位），当数值太接近时，GPU无法稳定判断哪个像素在前。

数学上的解释：

基础模型深度值 = 0.5000000 覆盖层深度值 = 0.5000001

深度缓冲区只能存储有限精度，当实际值为0.50000005时，可能会随机四舍五入，导致像素交替显示。

第四步：理解动画的影响

为什么静止时没问题，动画时才闪烁？

静止时：

基础顶点位置 = 骨骼矩阵 × 绑定姿势 覆盖顶点位置 = 骨骼矩阵 × 绑定姿势

理论上结果应该完全相同。

动画时：

  • 每帧重新计算顶点位置
  • 浮点数精度误差在矩阵运算中累积
  • 两个网格的蒙皮权重可能存在微小差异
  • 深度值产生波动，触发精度问题

解决方案

核心思路

给覆盖层一个微小的深度偏移，人为拉开两个模型的深度差距，但要足够小以免影响视觉效果。

方案一：修改Shader（最小改动）

在原Shader中添加Depth Offset支持，只增加几行代码：

Shader "J3/Particles/Additive"
&#123;
    Properties
    &#123;
        [HDR] _TintColor("Tint Color", Color) = (0.5,0.5,0.5,0.5)
        _MainTex("Particle Texture", 2D) = "white" &#123;&#125;
        _Multiplier("HDR Multiplier", Range(0,10)) = 1
        [IntRange] _StencilOpreration("Stencil Opreration", Range(1, 7)) = 0
        [HideInInspector] _StencilWriteMask("Stencil WriteMask",Range(0,255)) = 192
        
        // 1. 添加深度偏移参数（默认为0，不偏移）
        _DepthOffset("Depth Offset", Float) = 0
    &#125;

    SubShader
    &#123;
        Tags &#123; "Queue" = "Transparent" "IgnoreProjector" = "True" "RenderType" = "Transparent" &#125;
        Blend SrcAlpha One
        Cull Off Lighting Off
        ZWrite Off
        Fog &#123; Mode Off&#125;
        ColorMask RGB

        Pass
        &#123;
            Stencil
            &#123;
                Ref 255
                WriteMask[_StencilWriteMask]
                Comp Always
                Pass[_StencilOpreration]
            &#125;

            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma fragmentoption ARB_precision_hint_fastest
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            fixed4 _TintColor;
            float _Multiplier;
            float4 _MainTex_ST;
            
            // 2. 声明深度偏移变量
            float _DepthOffset;

            struct appdata_t
            &#123;
                float4 vertex : POSITION;
                fixed4 color : COLOR;
                float2 texcoord : TEXCOORD0;
            &#125;;

            struct v2f
            &#123;
                float4 vertex : SV_POSITION;
                fixed4 color : COLOR;
                float2 texcoord : TEXCOORD0;
            &#125;;

            v2f vert(appdata_t v)
            &#123;
                v2f o;
                o.vertex = UnityObjectToClipPos(v.vertex);
                
                // 3. 添加深度偏移逻辑（非0才生效）
                if (_DepthOffset != 0)
                &#123;
                    #if defined(UNITY_REVERSED_Z)
                        o.vertex.z -= _DepthOffset;
                    #else
                        o.vertex.z += _DepthOffset;
                    #endif
                &#125;
                
                o.texcoord = TRANSFORM_TEX(v.texcoord, _MainTex);
                o.color = v.color;
                return o;
            &#125;

            fixed4 frag(v2f i) : SV_Target
            &#123;
                half4 base = tex2D(_MainTex, i.texcoord);
                half4 color = 2.0f * i.color * _TintColor * base;
                return color;
            &#125;
            ENDCG
        &#125;
    &#125;
&#125;

方案三：C#脚本控制（无需改Shader）

using UnityEngine;

public class ApplyDepthOffset : MonoBehaviour
&#123;
    [Tooltip("深度偏移值，负值拉近覆盖层，建议-0.0001")]
    public float depthOffset = -0.0001f;
    
    [Tooltip("是否同时开启深度写入")]
    public bool enableZWrite = true;
    
    void Start()
    &#123;
        SkinnedMeshRenderer[] renderers = GetComponentsInChildren<SkinnedMeshRenderer>();
        
        // 假设第二个Renderer是覆盖层
        if (renderers.Length >= 2)
        &#123;
            Material overlayMat = renderers[1].material;
            
            // 检查是否有_DepthOffset属性
            if (overlayMat.HasProperty("_DepthOffset"))
            &#123;
                overlayMat.SetFloat("_DepthOffset", depthOffset);
                Debug.Log($"[Fix] Applied depth offset: &#123;depthOffset&#125;");
            &#125;
            else
            &#123;
                Debug.LogWarning("Material doesn't have _DepthOffset property");
                // 尝试使用其他方式
                overlayMat.SetInt("_ZWrite", 1);
            &#125;
            
            if (enableZWrite)
            &#123;
                overlayMat.SetInt("_ZWrite", 1);
            &#125;
            
            // 确保渲染队列正确
            overlayMat.renderQueue = 3000;
        &#125;
    &#125;
&#125;

参数调试记录

通过反复测试，发现 -0.0001 这个值最合适：

偏移量 效果
0 明显闪烁
-0.00001 轻微改善，仍有闪烁
-0.0001 完美解决
-0.001 无闪烁，但可能产生穿透

原理解析

为什么 -0.0001 有效？

假设基础模型的深度值是 0.5000000：

覆盖层原始深度值 = 0.5000000
覆盖层偏移后深度 = 0.5000000 - 0.0001 = 0.4999000

两个深度值的差距为 0.0001，远超深度缓冲区的精度误差范围，GPU可以稳定判断覆盖层更近。

为什么 Overdraw 视图不闪烁？

Overdraw视图的工作原理是忽略深度测试，直接显示所有像素的绘制次数。所以一旦排除深度测试的影响，问题就消失了。

动画放大的具体机制

// 每帧的计算过程
顶点位置 = 骨骼矩阵 × 权重 × 绑定姿势

// 浮点数误差累积
帧1: 0.5000000
帧2: 0.5000001  
帧3: 0.4999999
// 在精度阈值附近波动

经验总结

诊断技巧

  1. Overdraw视图是诊断深度问题的利器——问题是否与深度测试相关，一测便知
  2. 对比静态/动态表现——可以帮助定位问题性质
  3. 逐步调整参数——找到临界值，避免过度修正

预防措施

  1. 建模阶段：避免完全重合的面，保留微小间隙
  2. 材质设置：透明材质适当开启ZWrite
  3. Shader编写：使用Offset指令作为预防
  4. 多平台测试：不同平台深度精度有差异

适用范围

这个解决方案适用于以下场景：

  • 贴花（Decal）渲染
  • 多层UI重叠
  • 描边效果
  • 角色装备/特效覆盖
  • 任何两个共面或接近共面的几何体

结语

这个问题的解决过程告诉我们，渲染问题往往需要从多个角度去分析。静态正常不代表动态正常，Normal视图正常不代表底层逻辑正确。

掌握诊断工具（如Overdraw视图）、理解渲染原理（深度测试、Z-fighting），才能真正解决看似复杂的问题。

最后，-0.0001这个值我会记在小本本上，相信在很多类似场景都能派上用场。如果你也遇到类似问题，不妨试试这个方案。
